# Security Policy 🔐

## 🚨 Reporting a Vulnerability

I take security VERY seriously! If you find a security vulnerability in any of my projects:

### 📧 How to Report

1. **DO NOT** open a public GitHub issue
2. Email me directly at: **thakurrishab964@gmail.com** *(thakurrishab964@gmail.com)*
3. Include:
   - Description of the vulnerability
   - Steps to reproduce
   - Impact assessment
   - Suggested fix (if any)

### ⏱️ Response Time

- I'll respond within **48 hours**
- I'll keep you updated on the fix progress
- Fix will be deployed within **7 days**
- I'll credit you in the changelog (**if you want**)

## ✅ Security Practices I Follow

### In My Code

- ✅ Regular dependency updates (`npm audit`, `pip security`)
- ✅ Input validation and sanitization
- ✅ SQL injection prevention
- ✅ XSS protection
- ✅ CSRF tokens
- ✅ Secure password hashing (bcrypt)
- ✅ Environment variables for secrets (.env file)

### In My Development Process

- ✅ Code review before merging
- ✅ Security testing before release
- ✅ Penetration testing on critical projects
- ✅ OWASP Top 10 compliance
- ✅ Secure coding guidelines follow

### In My Infrastructure

- ✅ Firewalls enabled
- ✅ Regular security audits
- ✅ SSL/TLS encryption
- ✅ Rate limiting on APIs
- ✅ Secure authentication (OAuth 2.0)
